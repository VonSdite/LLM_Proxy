# Provider 模型测试口径

核对日期：2026-11-08。当前实现位于 `src/services/provider_model_test_service.py`，请求经过 `src/services/upstream_request_builder.py` 和协议转换器。以下结论来自代码审阅与模拟上游回归，未请求真实付费上游。

## 时间与用量

| 项目 | 当前实现 | 适用范围与限制 |
| --- | --- | --- |
| 首字延迟（TTFT） | 请求准备完成、调用上游 executor 前记录 `perf_counter()`，首个非空 `content` 或 `reasoning_content` 完整到达时计算时间差 | 包含连接、网络及上游等待，不含请求构建、Hook 和代理参数准备。忽略空角色、心跳和用量事件。思考片段同样计入，不保证是首个正文；重试只展示成功尝试的时间。 |
| TPS | `(completion_tokens - 1) / (last_output_at - first_output_at)`，时间单位秒 | 单请求生成阶段速度，排除首字等待与末尾用量、终止事件等待。首 Token 不属于首尾之间的生成区间，因此计数减一。 |
| 数据块时间 | 每次接收到非空网络数据块时记录单调时钟，块内事件共享时间 | 同块内多个 SSE 事件的本地解析耗时不形成生成区间。事件跨块时，以能够解码完整事件的数据块到达时间为准。 |
| 无法计算 | 输出用量缺失、输出不超过 1 Token、首尾没有正时间间隔时，TPS 为空 | 单数据块内返回全部输出也属于没有可观测区间。非流式成功响应的 TTFT 与 TPS 均为空，界面显示 —。 |
| 隐藏思考 | 已报告思考用量但没有思考增量、Responses 隐藏思考或摘要、Claude redacted thinking 均返回空 TPS | 避免将未观测生成过程的 Token 数除以正文生成区间；有有效输出时仍返回 TTFT 与可用状态。 |
| 可用状态 | 有正文或推理片段且未发现错误即为成功 | 不验证复制内容是否完整，也没有把正常结束标记作为成功的必要条件；仅证明本次请求收到有效模型输出。 |

例如请求在第 0 秒发起，首个输出在第 2 秒到达，末个输出在第 4 秒到达，上游报告输出 101 Token：TTFT 为 2000ms，TPS 为 `(101 - 1) / (4 - 2) = 50 Token/s`。末尾用量信息即使在第 20 秒才到达，也不延长生成区间。

正文和流式思考使用同一输出时间轴，Token 总数遵循上游 usage。系统不会通过字符数、SSE 事件数或数据块数推算 Token 数。一个数据块可能包含多个 Token，因此减一公式是客户端近似；分块、网络、缓冲和缺少思考用量明细仍会影响可比性。上游未声明隐藏思考用量时，系统无法凭模型名确认该差异。单次短请求不等价于服务端纯解码基准。

## 实际请求

基础请求使用 `stream=true`、`max_tokens=192`，省略 `temperature` 和 `top_p`，采用上游默认采样行为；提示模型原样复制 12 行固定英文文本。固定输出内容有助于减少任务差异；较短的输出上限适合低成本可用性检查。

- OpenAI Chat：保留基础字段，补充 `stream_options.include_usage=true`。
- Responses：输出上限转换为 `max_output_tokens`。
- Claude：使用 `max_tokens`。
- 模型名含 `glm` 的 Claude 接口：额外设置 `reasoning_effort=low`，转换为 `thinking={type: enabled, budget_tokens: 2048}`；总输出上限为 2240，思考预算以外保留 192 Token 额度。预算由协议转换器的同一辅助函数计算。
- 使用当前表单中的认证、指定 Auth Entry、代理、证书校验、超时、最大尝试次数和请求 Hook；Hook 可以继续修改实际请求。测试产生的成功用量会写入请求日志。

GLM Claude 是当前基准请求中唯一按模型名启用的特判；其他模型的思考策略采用上游默认行为。192 Token 对需要较长思考的模型仍可能不足，参数名兼容不代表已经识别所有模型的思考需求。

### 参数自适应

OpenAI Chat 在 HTTP 400 或 422 的错误信息明确表示 `max_tokens` 不受支持且指出 `max_completion_tokens` 时，会在下一次尝试中替换输出上限字段，额度保持不变。字段替换发生在 translator 和请求 Hook 之前，Hook 继续具有最终请求控制权。

每个模型测试最多进行一次字段切换，与普通重试共同遵守 `max_retries` 总尝试次数；值为 1 时仅发出一次请求。切换结果仅用于当前模型的后续尝试，不缓存到其他模型、Provider 或后续测试。认证失败、模型不存在、额度范围错误及未明确指出替代字段的错误继续按原错误返回。成功测试只记录一次用量。

[OpenAI 官方 Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 将 `max_tokens` 标为已弃用，指出其不兼容 o 系列模型；`max_completion_tokens` 的额度包括可见输出与思考 Token。本项目同时服务多种兼容上游，字段切换依据实际错误信息，不依赖模型名或别名推断。

## 与常见基准口径的对应

[NVIDIA GenAI-Perf 指标说明](https://github.com/triton-inference-server/perf_analyzer/tree/main/genai-perf#metrics) 区分首个响应时间、单请求生成吞吐量与整个基准的总吞吐量。

| 指标 | GenAI-Perf 定义 | 本项目对应关系 |
| --- | --- | --- |
| TTFT | 请求发出至首个响应收到 | 从请求发起计时，结束点要求有效正文或思考输出，忽略空事件；不同工具对首个响应的筛选仍可能不同。 |
| 每用户输出吞吐量 | 除首 Token 外的输出数 ÷ 请求生成阶段耗时 | 本项目采用这一公式，按流式首尾输出接收时间估算，并对已知不可靠的样本显示 —。 |
| 总输出吞吐量 | 整个基准的输出 Token 总数 ÷ 基准持续时间 | 本项目展示单个请求的生成速度，不测并发服务总吞吐量。 |

当前公式是常见单请求生成速度近似，Token 计数与时间范围需要对应；包含未观测思考、仅单块输出等样本保留可用性结果，性能数值为空。

## 后续建议

1. 默认测试提供可用性、首响应体验和生成阶段速度参考；严格跨模型比较时保持输出类型与用量口径一致。
2. 模型需要更长思考时，根据确认的能力信息为思考预算与正文输出分别预留额度；字段兼容和预算规划分开处理。
3. 需要严格性能比较时，使用更长的统一输出、多次采样和中位数，并区分首个推理片段与首个正文片段。
4. 精确的逐 Token 解码速度需要服务端 Token 时间戳或明确的分块 Token 计数；客户端接收间隔仅提供近似。

界面使用“结果、首字延迟、TPS”独立列，错误信息位于操作列。表头问号与模型映射测试详情共用说明文案，列出公式、单位、思考范围和 — 的条件。26 项模型测试回归覆盖协议请求、参数兼容、GLM 预算、生成区间公式、跨协议一致性、分块计时和隐藏思考边界。架构未变化。
