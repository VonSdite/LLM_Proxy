# Codex 额度刷新规则

项目分别维护认证文件列表快照、上游额度快照和重置卡快照。后台任务、数据面请求和 OAuth 页面都可以触发额度查询。页面读取列表时展示已有快照；额度查询访问 `https://chatgpt.com/backend-api/wham/usage`；重置卡查询访问 `https://chatgpt.com/backend-api/wham/rate-limit-reset-credits`。

## 频率和触发场景

| 场景 | 频率或条件 | 查询范围 | 上游查询 |
| --- | --- | --- | --- |
| 后台整轮刷新 | 默认每轮完成后等待 1 小时 | 全部符合后台查询条件的认证文件 | 额度；额度查询成功后查询重置卡 |
| 后台额度窗口到期 | 按已知额度窗口的 `reset_at` 计算唤醒时间 | 已到重置时间且快照尚未更新的认证文件 | 额度；额度查询成功后查询重置卡 |
| 账号进入新的粘滞使用段 | 该账号首次进入当前连续使用段时 | 即将用于模型请求的账号 | 额度 |
| 活跃账号成功请求 | 每个账号在当前使用段内每 10 分钟最多安排一次，延迟 60 秒执行 | 当前粘滞使用账号 | 额度 |
| 成功模型请求发现窗口到期 | 请求成功后发现已知 `reset_at` 已到且快照尚未更新时 | 完成本次请求的账号 | 额度 |
| 模型上游返回额度耗尽 | 识别到额度耗尽响应时立即尝试查询 | 发生额度错误的账号 | 额度 |
| 打开或重新加载 OAuth 页面 | 加载认证文件列表时 | 本地全部认证文件 | 展示已有快照 |
| OAuth 页面定时同步 | 每 60 秒；页面从隐藏变为可见、切回 Codex 页签时也检查一次 | 先读取本地全部文件，再查询到期文件 | 到期账号的额度和重置卡 |
| 单个认证文件手动刷新 | 每次点击 | 点击的认证文件 | 额度和重置卡 |
| 批量手动刷新 | 每次点击，按选中顺序逐个处理 | 当前筛选范围内选中的文件 | 额度和重置卡 |
| OAuth 登录完成或认证文件导入成功 | 完成后立即查询 | 新生成或成功导入的文件 | 额度和重置卡 |
| 使用重置卡成功 | 上游返回 `reset` 或 `already_redeemed` | 使用该卡的账号 | 服务端查询额度和重置卡；页面随后再查询一次额度 |
| 重置卡到期 | 按本地卡片过期时间更新展示 | 本地重置卡快照 | 更新页面展示 |

## 后台任务

`Application.run()` 启动一个 gevent 后台刷新任务。默认周期为 3600 秒，认证文件之间等待 10 秒。每个认证文件的网络请求耗时会累加到整轮耗时中，因此整轮开始时间之间的间隔约等于“一轮耗时 + 1 小时”。后台逐个查询，查询范围和数量影响一轮持续时间。

任务启动后先计算下一次周期刷新与已知窗口重置时间之间的较短等待时间。常规首次整轮查询约在启动 1 小时后开始；已有快照中的窗口重置时间可以提前触发对应账号查询。后台到期查询完成后继续沿用原有周期刷新计划。后台调度的最短等待为 1 秒，实际执行时间还受网络请求和前一轮任务耗时影响。

后台查询范围包含可读取、类型为 `codex`、存在 `access_token` 且当前未被标记为认证失败的认证文件。人工禁用、额度冷却中的账号仍可参与后台查询；人工禁用状态约束数据面的账号选择。无效 JSON、类型错误、缺少 access token 和已标记认证失败的文件进入跳过结果。

后台任务在服务运行期间持续存在。`oauth.enabled` 控制后台导航中的 OAuth 入口；后台任务生命周期由 `Application.run()` 控制。

## 模型请求触发

正常应用装配向 `CodexOAuthService` 提供日志仓储。一个认证文件进入新的粘滞使用段时，服务先查询额度并建立七天用量统计基线。同一使用段内持续使用该账号；账号切换、服务重启或当前账号退出使用段后，再次进入使用段会产生新的首次查询。首次查询失败时，模型请求继续执行；查询确认额度耗尽时，调度选择其他候选账号。

成功模型请求同时检查已有快照中的额度窗口是否到期。到期时，服务立即尝试更新该账号额度快照。另外，当前活跃账号的成功请求每 10 分钟最多安排一次延迟 60 秒的额度查询，用于更新七天用量统计的终点。该限频状态保存在进程内，账号进入新的使用段时重新建立。空闲账号通过后台周期和窗口到期任务更新快照。

上游 HTTP 400 或 429 响应中的 `error.type` 或顶层 `type` 为 `usage_limit_reached` 时，服务记录该账号的额度冷却状态、立即尝试查询额度，并继续尝试其他候选账号。快照查询失败时记录错误；原有模型错误和账号候选切换继续按数据面流程处理。

普通 429、`rate_limit_error`、`rate_limit_exceeded` 和缺少明确额度信号的响应按上游错误处理，保留错误信息和 `Retry-After`，并尝试其他候选账号。账号后续继续参与候选选择；这些响应的额度快照查询仍遵循后台、成功请求和手动查询等独立触发条件。

## 页面同步和手动刷新

OAuth 页面首次加载只请求本地认证文件列表、模型目录和已有状态。每分钟同步时先读取 `/api/oauth/codex/auth-files`；读取结果中的窗口已到 `reset_at` 且刷新时间尚未超过该重置点时，再逐个查询对应账号的额度和重置卡。

页面处于隐藏状态、当前页签为 Claude，或正在加载列表、批量刷新、导入、导出、删除、启停、查询额度、查询重置卡、消费重置卡时，本次自动同步跳过。页面从隐藏变为可见或切回 Codex 页签时，按相同条件执行同步。

额度窗口周期、剩余百分比和 `reset_at` 取自上游。缺少额度快照或窗口重置时间的认证文件，通过手动查询、进入新的使用段或后台整轮查询建立快照。

单个手动刷新按“额度查询 → 重置卡查询”的顺序执行。批量手动刷新只处理当前筛选范围内选中的认证文件，并逐个处理；页面批量刷新和导入后的刷新使用连续串行请求。后台任务中的 10 秒账号间隔适用于后台整轮与到期任务。

批量刷新期间，刷新、启停等互斥操作根据批量状态禁用；筛选仍可切换。批量启动时固定本次处理的认证文件列表，后续筛选切换影响展示与选择范围，本轮查询继续处理启动时的文件列表。

认证文件列表、额度和重置卡读取请求均采用 60 秒前端超时，覆盖连接、等待响应和读取 JSON 响应体。超时后显示错误，清除对应加载状态，批量任务继续处理后续文件并在结束后清除批量状态。一次账号刷新含两个串行读取请求，极端超时情况下约需 120 秒；多个文件的等待时间按数量累加。浏览器取消读取请求后，服务端已经发起的上游请求仍按服务端超时与锁机制结束。

筛选按钮原位更新选中状态和数量，保留按钮 DOM 节点。重置卡展示按过期时间更新；定时器单段等待上限为 `2^31 - 1` 毫秒，约 24.9 天。远期过期时间使用分段等待，尚未到期的中间段只重新安排定时器。

## 查询并发、认证和状态保存

同一个认证文件的额度查询使用进程内锁。普通查询遇到已有查询时返回 `skipped=true`、`reason=quota_refresh_in_progress` 和已有快照。账号进入使用段前的查询会等待锁并完成自身查询。重置卡查询沿用独立查询流程，多页面或多个触发来源仍可能分别请求重置卡。

小时周期、窗口到期、活跃账号限频和手动查询分别调度。10 分钟限频适用于活跃账号成功请求安排的查询；其他触发来源保留各自条件。多个来源连续查询同一个账号时，实际频率可以高于每 10 分钟一次。

额度查询使用认证文件当前的 access token。access token 刷新由数据面认证文件准备和上游未授权响应处理流程执行。控制接口请求优先使用认证文件中的 `proxy_url`，其次遵循全局 OAuth 出站代理设置；服务端上游请求使用 20 秒的连接与读取超时，并可以执行代理风险确认和重试。

access token 过期和认证失败后的刷新共用单账号进程内锁。服务取得锁后读取最新认证文件；其他请求已经更新有效 access token 时直接复用。认证失败的请求携带本次被拒绝的 access token，新 token 与它相同时执行 refresh token 交换，不同时复用新 token。不同账号分别使用独立锁。额度刷新和 token 刷新各自维护锁和触发条件。

额度快照、查询错误、刷新时间、重置卡列表和重置卡刷新时间保存在 `data/oauth/codex/.state/auth_files.json`。额度查询失败时更新错误与刷新时间，上一份成功快照保留。因此页面中的“上次刷新”也包含失败尝试的时间。重置卡查询失败时保留最近一次成功取得的卡片快照。

查询确认已启用账号的全部 Codex 额度窗口均有剩余额度时，服务清除该账号的额度冷却状态，并通知模型映射清理相应额度冷却。仍有耗尽窗口时，账号继续遵循冷却规则；人工禁用状态继续约束数据面调度。

## 默认值维护位置

| 默认值 | 位置 |
| --- | --- |
| 后台整轮间隔 3600 秒 | `src/services/codex_oauth_service.py`：`CODEX_QUOTA_AUTO_REFRESH_INTERVAL_SECONDS` |
| 后台账号间隔 10 秒 | 同文件：`CODEX_QUOTA_AUTO_REFRESH_FILE_DELAY_SECONDS` |
| 活跃账号安排间隔 600 秒 | 同文件：`CODEX_USAGE_ACTIVE_REFRESH_INTERVAL_SECONDS` |
| 活跃账号查询延迟 60 秒 | 同文件：`CODEX_USAGE_ACTIVE_REFRESH_DELAY_SECONDS` |
| 页面同步间隔 60 秒 | `src/presentation/templates/oauth.html`：`CODEX_AUTH_FILE_SYNC_INTERVAL_MS` |
| 页面读取超时 60 秒 | 同文件：`CODEX_AUTH_FILE_REQUEST_TIMEOUT_MS` |
| 重置卡定时器单段上限 | 同文件：`CODEX_RESET_CARD_TIMER_MAX_DELAY_MS` |

这些数值通过项目代码维护。当前系统设置页和 `config.yaml` 提供 OAuth 入口开关和网络设置；额度刷新间隔由上述代码常量提供。
